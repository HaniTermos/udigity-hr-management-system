# Batch 3 Independent Review: Calling and Follow-ups

- **Reviewer:** Independent Reviewer (did not write any Batch 3 content). Date: 2026-10-20.
- **Reviewed:** `docs/phase2/batch3/batch3-spec.md`, `batch3-mermaid.md`, `dependencies-and-open-items.md`.
- **Checked against:** `shared-baseline.md` SB-2 (incl. §10 R-01..R-13 and §11), `product-description.md` §2.3, §9, §10, §11, §16, §17 (and §2.1, §18 for tag checks). Cross-checked with `batch2-spec.md` (WF-ACCESS-001, Table RT, B7) and `batch4-spec.md` (E5 hand-off).
- **Scope:** functional errors only. Layout and style are not covered. This review approves nothing, and no Figma writes were made.
- **Mermaid lint:** I ran my own script, in the scratchpad and outside the project. All 10 flowcharts passed: every edge endpoint is defined, there are no orphan nodes, every decision has two or more exits and all of them are labelled, and the node counts (17–23) match the headers. The 4 state diagrams have no `note`, `classDef` or `style`, and no undeclared states. The functional routing errors are listed below.

## Verdict

**Ready after listed functional fixes.**

The batch was written against SB-1. It has not taken in the SB-2 contracts B7, B8 or E5, or rulings R-08 and R-09. It also has gaps of its own in the D2 marker, the outcome rule for Accepted, and reminder retargeting. Some things are already correct and need no change: the four outcomes stay distinct and non-sequential, a call attempt is kept separate from the current outcome, the reservation lifecycle is complete (renewal is a self-transition, tab switching never releases, and save always happens before release), follow-ups and reminders are independent (D5), job time is kept separate from event time, the C6 re-check is present, DEC-016 is left unselected with reason and user recorded, and the outcome rules stay a table (R-10).
